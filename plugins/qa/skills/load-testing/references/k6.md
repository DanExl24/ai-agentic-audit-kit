# Notas: k6

Scripts en JavaScript; un binario en Go que genera la carga. Termina con código distinto de 0 si fallan los umbrales, así que sirve como puerta de CI.

## Prueba de carga con modelo abierto

```js
// load/checkout.k6.js
import http from 'k6/http';
import { check, sleep } from 'k6';
import { SharedArray } from 'k6/data';

const BASE_URL = __ENV.BASE_URL || 'http://localhost:8080';
const products = new SharedArray('products', () => JSON.parse(open('./data/products.json')));

export const options = {
  scenarios: {
    browse: {
      executor: 'ramping-arrival-rate',   // modelo abierto: iteraciones por segundo
      startRate: 10,
      timeUnit: '1s',
      preAllocatedVUs: 50,
      maxVUs: 300,
      stages: [
        { target: 100, duration: '5m' },  // subida
        { target: 100, duration: '15m' }, // meseta en el tráfico esperado
        { target: 0, duration: '2m' },
      ],
    },
  },
  thresholds: {
    http_req_failed: ['rate<0.01'],
    'http_req_duration{endpoint:product}': ['p(95)<300', 'p(99)<800'],
    checks: ['rate>0.99'],
    dropped_iterations: ['count<100'],     // el generador no llegó a la tasa pedida
  },
};

export function setup() {
  const res = http.post(`${BASE_URL}/api/auth/login`, JSON.stringify({
    email: __ENV.LOAD_USER, password: __ENV.LOAD_PASSWORD,
  }), { headers: { 'Content-Type': 'application/json' } });
  return { token: res.json('token') };
}

export default function (data) {
  const product = products[Math.floor(Math.random() * products.length)];
  const params = { headers: { Authorization: `Bearer ${data.token}` }, tags: { name: 'GET /api/products/:id', endpoint: 'product' } };
  const res = http.get(`${BASE_URL}/api/products/${product.id}`, params);
  check(res, { 'status 200': (r) => r.status === 200, 'tiene precio': (r) => r.json('price') !== undefined });
  sleep(Math.random() * 2 + 1);
}
```

- `tags: { name: ... }` agrupa las URLs con IDs en una sola métrica (si no, cada ID es una serie distinta); una etiqueta propia simple (`endpoint: 'product'`) permite umbrales por endpoint (`http_req_duration{endpoint:product}`).
- Ejecutores: `constant-vus` y `ramping-vus` (cerrado), `constant-arrival-rate` y `ramping-arrival-rate` (abierto).
- `dropped_iterations > 0` en modelo abierto significa que faltaron VUs o que el sistema no da más: súbelos o es un dato del límite.
- Un umbral con `abortOnFail: true` corta la prueba en cuanto se incumple (útil en estrés para no hundir el entorno).

## Ejecución

```bash
k6 run -e BASE_URL=https://staging.example.com load/checkout.k6.js
K6_WEB_DASHBOARD=true k6 run load/checkout.k6.js           # panel en vivo y informe HTML
k6 run --out json=results.json load/checkout.k6.js          # resultados crudos
```

Las credenciales van por `-e` o variables de entorno de CI, nunca en el script.

## Smoke en CI

Un escenario `constant-vus` con 1–2 VUs durante 1 minuto y los mismos umbrales; como k6 sale con error si se incumplen, basta un paso `k6 run` en el pipeline (hay acciones oficiales de Grafana para instalar k6 en GitHub Actions, o la imagen `grafana/k6`).

## Otros

- Escenarios múltiples en el mismo archivo con pesos distintos (lectura, búsqueda, compra) para la mezcla real.
- Navegador (`k6/browser`) para medir Web Vitals bajo carga, con muy pocos VUs: es caro.
- Distribución a gran escala: varias instancias de k6 o el servicio en la nube de Grafana.
