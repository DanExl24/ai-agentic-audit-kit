# Checklist de auditoría de especificación

Ajusta la severidad con el [estándar de Producto](../../../standards/severity.md).

- [ ] Alcance, actores, exclusiones, dependencias y responsable de aprobación están identificados. **MEDIUM**
- [ ] Cada requisito tiene ID estable, fuente, estado y un resultado verificable. **HIGH si afecta un flujo crítico**
- [ ] La especificación conserva las preguntas y los supuestos abiertos. Las diferencias con el código o con el backlog tienen evidencia y estado. **HIGH si la discrepancia cambia una decisión de implementación**
- [ ] Los RNF tienen métrica, umbral, escenario, condiciones y método. Los valores pendientes están identificados. **MEDIUM**
- [ ] Las interfaces y restricciones citan un contrato o una decisión, y sus fallos relevantes tienen cobertura. **HIGH en interfaces críticas**
- [ ] Toda técnica exigida en un requisito acordado tiene una fuente explícita. Las referencias de diseño se distinguen del resultado verificable. **MEDIUM**
- [ ] Los enlaces resuelven y los criterios de verificación distinguen evidencia disponible de trabajo previsto. **MEDIUM**
